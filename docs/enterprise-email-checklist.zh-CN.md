# 企业邮箱开工与验收清单

版本：2026-11-27｜给客户负责人、业务人员与实施者共同填写。

**这份清单从“未执行”开始。**已完成的是研究和模板；真实账号、DNS、发信与恢复测试必须在客户项目中执行后才能打勾。详细步骤和官方原始链接见同套《出海企业邮箱：从开通到可靠运营》。

## 1. 先做三个决定

- [ ] 已有邮箱能否保留：先做本清单验收，缺项才升级或迁移。
- [ ] 谁接待：一个主负责人＋一个替补或明确的单人应急安排。
- [ ] 网站需求：仅显示邮箱／有表单并人工巡检／需要自动补漏。

**默认参考方案：**每人独立工作账号，公开 sales@ 角色地址；多人采用共享/委派，单人可评估别名；网站先保存询盘，再发提醒。已有能达标的服务优先沿用。无历史系统的小团队可先评估 Zoho 中国区付费方案；Outlook多人协作重点比较合适云环境的 Exchange Online；本地采购支持优先时比较阿里邮箱。

## 3. 开通与技术配置顺序

1. [ ] 选对区域与计划，并实测管理员、员工的实际网络。
2. [ ] 客户持有注册、账单、MFA和独立恢复渠道，至少一个恢复途径不依赖本企业邮箱域名收信；实施者只用必要权限。
3. [ ] 在真实租户验证域名，先创建人员/业务收件地址和许可。
4. [ ] 有旧邮箱时先完成盘点、迁移准备和回退计划。
5. [ ] 准备SPF/DMARC与可生成的DKIM；按厂商激活顺序完成签名，不硬性假定所有DKIM都能在激活前配置。
6. [ ] 根据批准的变更表改MX/相关记录，保留网站与无关DNS。
7. [ ] 配置共享权限、正确回复身份、共享已发送记录和必要客户端。
8. [ ] 接网站邮箱/按钮；有表单时做留底、通知和故障处理。
9. [ ] 完成下方实测，客户演示独立操作后签认。

|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

不能填通用猜测值：MX、域名验证值、DKIM选择器/目标及公钥必须来自客户当前租户。SPF同名只一条有效策略，包含嵌套的DNS查询预算要核验。新DMARC策略先观察并安排报告负责人；已有成熟策略先审计，不自动降级或升级。2026标准下，不把pct百分比当作可靠灰度，也不把所有日常邮箱域的reject当作统一验收终点。

Google新组织启用Gmail后可能需等待24–72小时才可生成DKIM；这类等待写进待办，不用示例公钥代填。该规则原文：[Set up DKIM](https://knowledge.workspace.google.com/admin/security/set-up-dkim)。

## 5. 客户交接演示：不用开发者代点

- [ ] 我能打开业务邮箱，找到询盘，并以正确身份回复。
- [ ] 我知道怎样看垃圾/隔离和网站后台未处理记录。
- [ ] 我知道提醒邮件没来时去哪里查原始询盘。
- [ ] 同事或替补能看已回复内容，并知道谁负责下一步。
- [ ] 我能联系服务商支持、检查账号异常并走恢复流程。
- [ ] 我知道人员离职先撤权、保留和转交业务，再处理许可/删除。
- [ ] 域名、邮箱、发信服务、关键应用凭据的到期负责人明确。
- [ ] 自动化缺项、等待生效和未测场景都有负责人和复核日期。

日常签名只包含真实名称、职责、网站和工作联系方式。客户收款资料变更另用已知联系人渠道确认；异常时检查会话、令牌、转发、收件规则和应用授权，不只改一个密码。
